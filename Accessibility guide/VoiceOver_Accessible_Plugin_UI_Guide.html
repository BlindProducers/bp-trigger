VoiceOver Accessible Plugin UI Guide for JUCE

Purpose

This document captures the accessibility patterns used in the BP-Convolution plugin UI so they can be reused in other JUCE audio plugins. The goal is a plugin that works naturally with macOS VoiceOver: controls have names, values, roles, help text, predictable keyboard focus, useful groups, accessible lists/tables, and spoken feedback when important state changes.

Core Principles

  • Every interactive control must have a clear accessible title, description, and help text where useful.
  • Every major visual section should also be an accessibility group.
  • Keyboard focus must be intentional. Do not rely on the default tab order if the UI has sections, panels, browsers, or modal overlays.
  • Painted text is not enough. If a row, table cell, or custom control is only drawn with Graphics::drawText, VoiceOver will not know what it says unless you expose a name.
  • Actions that change context, load files, open panels, close panels, or navigate folders should post an accessibility announcement.
  • Keyboard shortcuts should work when focus is inside the control that visually owns the interaction, not only when the parent component has focus.

Accessibility Groups

Use groups for major plugin sections such as IR Controls, Filter Controls, Output Controls, Settings, and IR Browser. A group gives VoiceOver users a mental map of the plugin.

Component setup

setFocusContainerType(juce::Component::FocusContainerType::keyboardFocusContainer);

Group accessibility handler

class IRBrowserAccessibilityHandler : public juce::AccessibilityHandler
{
public:
    IRBrowserAccessibilityHandler(IRBrowser& c)
        : AccessibilityHandler(c, juce::AccessibilityRole::group) {}

    juce::String getTitle() const override { return "IR Browser"; }
};

std::unique_ptr<juce::AccessibilityHandler> IRBrowser::createAccessibilityHandler()
{
    return std::make_unique<IRBrowserAccessibilityHandler>(*this);
}

When to create a group

  • Create a group for each logical section of the plugin.
  • Create a group for overlay panels such as Settings.
  • Create a group for complex controls such as an IR browser, preset browser, modulation matrix, or routing table.
  • Avoid making every tiny row or label its own group. Too many groups make navigation noisy.

Labels, Titles, Descriptions, and Help Text

JUCE exposes several useful strings to accessibility clients. Use them consistently.

Method Use it for Example
setTitle() The short accessible name of a control. loadButton.setTitle("Load IR");
setDescription() A slightly longer explanation of what the control changes or does. setDescription("Load the selected WAV impulse response");
setHelpText() Keyboard instructions or interaction hints. setHelpText("Select a WAV file, then press Enter");
Label::attachToComponent() Visual labels for sliders and controls. startLabel.attachToComponent(&startSlider, true);

Button example

loadButton.setButtonText("Load IR");
loadButton.setWantsKeyboardFocus(true);
loadButton.setTitle("Load IR");
loadButton.setDescription("Load the selected WAV impulse response");
loadButton.setHelpText("Select a WAV file in the browser, then press Enter on this button");
loadButton.onClick = [this] { loadSelectedFile(); };

Keyboard Focus

VoiceOver users often combine VoiceOver navigation with normal keyboard focus. The plugin should support both.

Make interactive controls focusable

button.setWantsKeyboardFocus(true);
slider.setWantsKeyboardFocus(true);
listBox.setWantsKeyboardFocus(true);

Use explicit focus order inside dense sections

startSlider.setExplicitFocusOrder(1);
endSlider.setExplicitFocusOrder(2);
sizeSlider.setExplicitFocusOrder(3);
decaySlider.setExplicitFocusOrder(4);
reverseButton.setExplicitFocusOrder(5);
irGainSlider.setExplicitFocusOrder(6);

Section navigation shortcuts

BP-Convolution uses comma and period to jump between major focus groups. This is useful in plugin UIs where tabbing through every control can be slow. 

bool PluginEditor::keyPressed(const juce::KeyPress& key)
{
    if (key.getKeyCode() == ',' || key.getTextCharacter() == ',')
    {
        focusGroup(-1);
        return true;
    }

    if (key.getKeyCode() == '.' || key.getTextCharacter() == '.')
    {
        focusGroup(1);
        return true;
    }

    return false;
}

Sliders

Sliders should expose a short name, a meaningful description, and help text that explains keyboard increments. If a slider needs custom fine/coarse steps, subclass it and handle arrow keys explicitly.

Standard accessible slider setup

sizeSlider.setSliderStyle(juce::Slider::LinearHorizontal);
sizeSlider.setTextBoxStyle(juce::Slider::TextBoxLeft, false, 50, 20);
sizeSlider.setWantsKeyboardFocus(true);
sizeSlider.setTitle("Size");
sizeSlider.setDescription("Time stretch the impulse response, 0.1x to 4.0x");
sizeSlider.setHelpText("Use arrow keys to adjust by 0.1, shift plus arrows for 0.01");
sizeSlider.setExplicitFocusOrder(3);

Custom arrow-key slider pattern

class AccessibleSlider : public juce::Slider
{
public:
    AccessibleSlider(double normalStep, double fineStep)
        : step(normalStep), fine(fineStep) {}

    bool keyPressed(const juce::KeyPress& key) override
    {
        auto delta = key.getModifiers().isShiftDown() ? fine : step;

        if (key == juce::KeyPress::leftKey || key == juce::KeyPress::downKey)
        {
            setValue(getValue() - delta, juce::sendNotificationSync);
            return true;
        }

        if (key == juce::KeyPress::rightKey || key == juce::KeyPress::upKey)
        {
            setValue(getValue() + delta, juce::sendNotificationSync);
            return true;
        }

        return juce::Slider::keyPressed(key);
    }

private:
    double step;
    double fine;
};

Accessible Lists and Tables

A common VoiceOver failure is a list whose rows are visually drawn but not named. In JUCE, if you use ListBoxModel::paintListBoxItem(), you must also override getNameForRow(). Otherwise VoiceOver may announce generic names such as "Row 1".

Accessible row names

juce::String IRBrowser::getNameForRow(int rowNumber)
{
    if (rowNumber < 0 || rowNumber >= currentItems.size())
        return {};

    const auto& item = currentItems.getReference(rowNumber);
    return item.isDirectory() ? "Folder, " + item.getFileName()
                              : item.getFileName();
}

Painted rows are visual only

void IRBrowser::paintListBoxItem(int rowNumber, juce::Graphics& g,
                                 int width, int height, bool rowIsSelected)
{
    if (rowNumber < 0 || rowNumber >= currentItems.size())
        return;

    if (rowIsSelected)
        g.fillAll(juce::Colours::lightblue.darker());

    auto& item = currentItems.getReference(rowNumber);
    auto prefix = item.isDirectory() ? "[Folder] " : "";
    g.drawText(prefix + item.getFileName(), 10, 0, width - 20, height,
               juce::Justification::centredLeft);
}

The text drawn above is not the same as accessible text. The accessible text comes from getNameForRow().

List/table checklist

  • Set a title on the list, such as listBox.setTitle("File list").
  • Set a useful description explaining allowed keys and row types.
  • Override getNameForRow() for every row.
  • Keep row names concise but meaningful: "Folder, Halls" is better than just "Halls".
  • Update selected row state after refreshes so VoiceOver lands on the expected row.
  • Never hold references into a row array while refreshing the list. Copy the item first.

File Browser Pattern

A plugin file browser should preserve context. After loading a file, the user should remain in that folder. After closing and reopening the plugin editor, restore the browser to the last loaded file when possible.

Restore browser to last loaded IR

auto lastLoadedIR = juce::File(PluginSettings::getInstance().getLastLoadedIR());
if (lastLoadedIR.existsAsFile())
{
    browser.showFile(lastLoadedIR);
}
else
{
    auto defaultFolder = PluginSettings::getInstance().getDefaultIRFolder();
    if (defaultFolder.isDirectory())
        browser.navigateToFolder(defaultFolder);
}

Load selected file without losing folder context

void IRBrowser::loadSelectedFile()
{
    auto row = listBox.getSelectedRow();
    if (row < 0 || row >= currentItems.size())
        return;

    auto item = currentItems.getReference(row);
    if (!item.existsAsFile())
        return;

    selectedItemPath = item.getFullPathName();

    if (fileSelectedCallback)
        fileSelectedCallback(item);
}

Backspace and Browser Shortcuts

If a shortcut should work while focus is in a child control, implement the shortcut in that child control. For example, Backspace should work when focus is inside the file list, not only when the parent browser component has focus.

Subclass the list box for Backspace

class BrowserListBox : public juce::ListBox
{
public:
    bool keyPressed(const juce::KeyPress& key) override
    {
        if (key == juce::KeyPress::backspaceKey)
        {
            if (onBackspace)
                onBackspace();

            return true;
        }

        return juce::ListBox::keyPressed(key);
    }

    std::function<void()> onBackspace;
};

Wire it to folder navigation

listBox.onBackspace = [this] { goUp(); };

Announcements

Use announcements for important changes that are not otherwise obvious from the focused control. Good examples include loading an IR, opening or closing a panel, navigating to another folder, and adding or removing a folder. 

juce::AccessibilityHandler::postAnnouncement(
    "Loaded impulse response: " + file.getFileName(),
    juce::AccessibilityHandler::AnnouncementPriority::high);

Announcement guidelines

  • Keep announcements short.
  • Include the changed item name when possible.
  • Use high priority for user-initiated actions such as loading a file or opening settings.
  • Do not announce every slider movement if the slider already exposes its value. That becomes noisy.

Modal and Overlay Panels

Settings panels and overlays should behave like separate accessible regions.

  • Give the overlay its own accessibility group title.
  • Move focus into the overlay when it opens.
  • Provide a clear Close button with title, description, and help text.
  • Announce opening and closing.
  • When the overlay closes, return focus to a sensible control, usually the button that opened it.
settingsButton.onClick = [this]
{
    settingsPage.setVisible(true);
    settingsPage.toFront(true);

    juce::AccessibilityHandler::postAnnouncement(
        "Settings opened",
        juce::AccessibilityHandler::AnnouncementPriority::high);
};

Common Bugs to Avoid

  • Generic rows: If VoiceOver says "Row 1", override getNameForRow().
  • Dangling row references: Copy a selected file before calling any function that refreshes or clears the list.
  • Lost browser location: Store the last loaded file path and restore the browser to that file's parent folder.
  • Shortcut works only sometimes: Put the shortcut handler on the focused child control, such as the list box.
  • Silent state changes: Post announcements for loading, navigation, opening, closing, adding, and removing.
  • Duplicate load paths: If a browser owns file selection, put the Load button in the browser, not in an unrelated controls section.
  • Painted-only labels: Anything drawn manually must also be represented through accessible names, titles, or handlers.

Reusable Accessibility Checklist

Before coding

  • List the major UI groups.
  • Define the keyboard route through the plugin.
  • Decide which controls need custom keyboard behavior.
  • Identify any painted rows, tables, meters, graphs, or custom components that need explicit accessible names.

For every group

  • Set keyboardFocusContainer when the group contains multiple controls.
  • Add an AccessibilityHandler with AccessibilityRole::group.
  • Return a clear title from getTitle().

For every button

  • Call setWantsKeyboardFocus(true).
  • Set button text.
  • Set title, description, and help text.
  • Announce important action results.

For every slider

  • Set title, description, help text, and focus order.
  • Use text boxes when helpful for exact values.
  • Implement custom arrow behavior for nonstandard increments.
  • Attach a visual label where appropriate.

For every list or table

  • Set list title and description.
  • Override row names.
  • Keep selection stable after refreshes.
  • Make Enter and Backspace behavior predictable.
  • Expose load/open/delete actions through buttons when the action is not obvious.

Before release

  • Navigate the whole plugin with keyboard only.
  • Navigate the whole plugin with VoiceOver.
  • Verify row names, slider names, button names, and group names are announced correctly.
  • Verify shortcut keys work when focus is on the child component that users naturally interact with.
  • Close and reopen the plugin editor and confirm state restoration.
